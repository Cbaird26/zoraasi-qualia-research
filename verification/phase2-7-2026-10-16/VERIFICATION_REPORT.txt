Source audit and corrections
----------------------------
Within the supplied script, the gated and ungated memory arms share the same base updates and storage policy. That comparison does isolate the combined retrieval filter, including downstream feedback. However, its arm named phase25_ungated is not the actual Phase 2.5 engine: storage now also requires stable_steps >= 10 and fast/slow distance < .08, and the merge radius changes from .12 to .16. Calling all differences from published Phase 2.5 retrieval-only is incorrect.

The corrected proposal preserves those proposed storage rules under consolidation_mode="proposal". A separate consolidation_mode="phase25" restores actual Phase 2.5 storage and ordered likelihood arithmetic. With the new filters disabled, every forecast is asserted equal to the pinned Phase 2.5 implementation; no-memory forecasts are also asserted equal to pinned Phase 2.5 without episodic memory.

Fixed: the marginal comparator must be scored before seeing the current outcome; previously its post-update probability biased the valence statistic. Snapshot likelihood and snapshot distance now use the same pre-update slow tuple; the source used a pre-update likelihood but post-update distance. Added explicit learned initialization/full reset, finite/probability/input validation, zero-capacity handling, and counter diagnostics. Removed the overwritten duplicate norm assignment. Legacy flags preserve each timing bug as a separately measured ablation. No performance threshold or learning-rate parameter was selected using test outcomes.

The original distance code rejects values strictly below .20, so equality is allowed; the prose writes a strict greater-than condition. The correction retains the code convention and documents it. Bernoulli KL is mathematically nonnegative; the implemented endpoint clipping is a numerical regularization, not the infinite boundary divergence.


Corrected experimental design
-----------------------------
Training: 24 independent stationary-A trials of 30 states (696 within-trial transitions), Beta(1,1) row estimates and learned marginal. Every learner receives the same estimates and observations. Test streams use distinct RNG namespaces from training. All predictions are recorded before the current outcome is used. Oracle-regime forecasts are explicitly privileged reference predictions, not a deployable competitor.

Fresh seed banks: validation 121000000–121000029; primary 101000000–101000099; follow-up 111000000–111000099. Earlier phase seeds are not reused. The manifest records the architecture, thresholds, checksums and baseline selections before evaluating these seeds. This internal sequencing is not an external preregistration.

Baseline search: 50 EMA rates and 384 CUSUM configurations, chosen by mean validation Brier on mixed_9 only. Families retain the supplied unclipped updates with learned initialization. Earlier selected settings are also retained as fixed controls. Selected settings: {"cusum": {"drift": 0.4, "lr": 0.18, "threshold": 1.0}, "ema": {"lr": 0.27}}. Search grids are finite and tuned to one scenario, not a proof of optimality.

mixed_9 consists of nine 45-transition blocks A/B/A/B/C/D/E/B/A: 405 overall observations, 135 novel, 180 familiar-return and 80 first-ten post-switch observations. The first A and B blocks are excluded from the familiar-return score. Six prior generators are copied unchanged, including stationary, recurring, random unseen schedules, and altered initial-state probabilities. Their scope masks are explicit in the harness.

proposal_full includes the proposed storage changes plus both filters; proposal_ungated removes the filters with that storage policy fixed. retrieval_only_full applies both filters to actual Phase 2.5 storage; anti_only and kl_only isolate the filter components. actual_phase25 and actual_phase26 are imported unchanged from commit e9df7d0d58019ae8a0bb1cd6db5d311025171af4. Comparisons are paired within seed; the same seeds across seven scenarios do not create 1,400 independent replicates for a pooled inference.

Component ablations are grouped: the anti-rollback component combines slow-likelihood advantage with distance; the KL component combines row coverage with the KL cutoff. proposal and retrieval-only modes also use algebraically equivalent grouped versus sequential likelihood summation for exact pinned compatibility, so their difference is not a bitwise storage-only intervention. Within each storage mode, filter comparisons keep arithmetic fixed. Whole-block event counters cannot establish first-ten event rates; only the prediction losses are explicitly scored over that shorter interval.

Mathematical checks and limits of the proposed explanation
----------------------------------------------------------
The flow identity is correct: N01 - N10 = X_last - X_first for a contiguous binary path. The revised eight-transition example (1,1,1,1,0,1,1,1,1) has counts (6,1,1,0). For an ordered row path, the Beta(1,1) integral is B(n1+1,n0+1); the example gives row-1 log evidence -4.025351691, row-0 log evidence -0.693147181 and snapshot joint log-ratio +0.419514898. Passing this compatibility comparison alone does not prove that an actual retrieval occurs.

Integrating a prior is not a programming bug merely because it produces an Occam penalty. The term -ln(n+1) is part of the identity B(k+1,n-k+1)=1/((n+1) choose(n,k)); it is not the complete penalty relative to the fitted likelihood. For the 6-success/1-failure row, evidence minus fitted log likelihood is -1.154537463, not -ln(8). Adaptive candidate selection also prevents interpreting the raw threshold as a calibrated false-novelty probability.

The quoted KL values are correct: KL(.75 || .28)=0.474515128984 and KL(.25 || .28)=0.002284324563. But one compatible row is insufficient for both-row acceptance. The proposed engine has a six-transition window: the trailing counts of the worked eight-transition path become (4,1,1,0), and row-1 KL is 0.131633223163, already above .12.

Exhaustive enumeration of all 128 binary paths with six transitions finds only three paths compatible with exact A=(.92,.28) under both row-KL conditions: 0000111, 0001111, 0011111. All start in state 0. Under stationary A their total probability is 7.6868829184%; absent-row rejection alone has probability 55.5617132089%. Under stationary D=(.88,.88), the same A compatibility event still has positive probability 0.8776923218%. These are exact probabilities of coverage plus KL compatibility for a fixed exact snapshot, not measured retrieval rates or false-positive rates of the entire engine.

The claimed mathematical impossibility of early old-regime retrieval is false without assumptions about the slow trace. A full-update counterexample starts with fast=slow=(.5,.5), arousal=.65, stored A and five old transitions 0→0→0→1→1→1; the first new transition 1→1 completes the compatible six-transition window, passes every proposed guard and retrieves A. This is a legal constructed state, not a claim about its frequency or reachability from the default initialization. A slow trace equal to the old snapshot would block it, but the implementation cannot assume that equality.

The supplied anti-rollback unit test is not specific to the new guard: its snapshot already fails the ordinary fast-likelihood margin (+.034458392 < .30), and its slow advantage is negative. Separately, replaying pinned Phase 2.6 seed 71000000 exactly reproduces its stored scores, but only 1 of 8 switches has any retrieval during the first three updates and none at zero-based offset 1. At the block-7 retrieval, cooldown values are 5,4,3,2,1 on the next five steps, zero on the sixth, and another retrieval occurs at offset 7. Therefore the supplied “every switch,” “steps 2–7 lockout,” and “never triggered again” narratives are not established. One replay refutes a universal assertion; it does not measure population frequency or identify the selected snapshot as an old regime.

The stationary-noise explanation is plausible but conditional. The square-error learning-rate increment .22×.92²=.186208 is correct; a cosine-scaled continuity value equals exp(-.90×.92) only if cosine similarity is one. Prior ablations support a speed/stability tradeoff. An exact causal claim about a particular switch requires logged events and interventions, not a narrative inferred from aggregate loss.


What the findings mean and the next discriminating experiment
-------------------------------------------------------------
The measured tradeoff is concrete. Primary overall Brier is .174898 for the corrected full proposal versus .173447 for its shared-storage ungated control, .170785 for actual Phase 2.5, .170441 for Phase 2.6 and .169840 for selected CUSUM; the ordering persists on follow-up seeds. The retrieval-only full filter is closer to actual Phase 2.5 but also worsens overall and early-switch Brier. Its scores are much closer to the KL-only ablation than to anti-only, suggesting the coverage/KL component accounts for most of the measured filtering effect in this experiment. These are measured policy effects, not proof of the supplied rollback narrative.

This proposal makes memory use more selective, but selectivity alone is not recognition. Six observations cannot guarantee regime identity when all regimes assign positive probability to the same binary paths. Jeffreys smoothing stabilizes sparse estimates while also pulling them away from extreme snapshots; the fixed .12 cutoff strongly constrains which windows can match A. Slow-trace distance is a heuristic measure of novelty, not an oracle for the departed regime.

A useful next version would declare the target tradeoff before running: retain a specified familiar-return gain while bounding novel and first-ten excess loss by explicit margins. Calibrate coverage/window length and thresholds on validation streams; then freeze them before new evaluation. Include row-specific information diagnostics, change-point-aware windows, variation of the current .65 snapshot blend weight, memory age/capacity sensitivity, and unseen transition matrices and dwell lengths. Compare the complete storage-plus-retrieval policy with its components, and keep strong adaptive baselines. These are proposed future experiments, not implemented or validated improvements.

The legitimate result is an executable, auditable adaptive prediction system with measurable memory-related tradeoffs. The scalar names arousal, valence and continuity denote defined numerical state updates. Predictive gains, internal states or retrieval events do not establish subjective experience, consciousness, synthetic qualia or physical confirmation of MQGT-SCF. Those claims would require independently specified evidence linking the model to the asserted phenomenon.
